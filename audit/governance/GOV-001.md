## Scientific Inquiry run
1. Question (precise): Is the absolute rule 'the base code does not change' consistent with canon's own Falsifiability Register, and is the author's scoped rule forced or only chosen?
2. What an answer must look like: Either (a) the absolute rule and ◇ are consistent, leaving the scoping a pure operator choice (stipulation); or (b) they conflict, and only the scoped rule is consistent with canon (forced-fill).
3. Falsifiability condition: Find a reading of ◇ under which a fired falsifier for the Universal Algorithm would *not* require changing the base code. If one exists, the scoping is not forced.
4. Variables: measurable / bounded / held open: Measurable: the texts. Bounded: what 'revision' in ◇ covers. Held open: whether any falsifier will ever fire (no domain audit has yet found DETECT → PROCESS → RESPOND absent; Phase 5 tests this).
5. Test designed: Read the absolute rule against every ◇ statement that names the base algorithm; test each candidate reading.
6. Data (unfiltered): ◇ names a falsifier whose object is the base code itself ('Universal Algorithm (3 operations)') and says met conditions *require revision of the framework*. Under the absolute rule, a fired falsifier could never revise the base, so that ◇ row would be a falsifier that can never have consequences — which ◇'s own preamble rules out: *'A framework that cannot be disproved by any conceivable evidence is not a framework — it is a belief.'* The only reading of 'revision' that excludes the base is one where the Universal Algorithm row is decorative; that reading contradicts the row's presence. v5.3 Q1 ('invoke, not rewrite') constrains *the meta-tier's* operation on the base, not reality's — it is compatible with both readings.
7. Variable Principle applied: Nothing is filled: the scoped rule does not say the base code is wrong, only what happens if a falsifier fires. Whether one fires stays open.

## Forcing Test
- Test A (Ground): Within-system — a consistency question between two canonical texts.
- Test B (Uniqueness): Two candidates enter (absolute; scoped). The absolute rule conflicts with ◇'s Universal Algorithm row and preamble; only the scoped rule survives.
- Test C (Direction): Direction runs reality → text: ◇ already points it that way ('would, if met, require revision').
- Test D (Falsifiability): Falsifier in step 3 did not fire: no reading of ◇ both keeps the Universal Algorithm row meaningful and forbids base revision.
- **Outcome:** forced-fill — the scoping is **forced by canon's own ◇**, not merely an operator decision. The exact wording is a stipulation (presentation).

## Anti-Operation (the gap this opens)
If the base code can be revised by reality, **what measurement would fire its falsifier?** ◇'s falsifier is 'a domain where DETECT → PROCESS → RESPOND is entirely absent' — but the three operations are defined broadly enough that it is unclear what 'absent' would look like. The falsifier's operational form is the new open edge; Phase 5 (domain audit) is where it gets tested.

**Drafted replacement wording (apply in v5.5 draft only):**
- `CONTRIBUTING.md`, *The one rule*: "**The base code holds until reality contradicts it.** It is not rewritten for convenience, preference, or from inside the system (v5.3: invoke, not rewrite). Only a reproduced observation that fires a stated falsifier (v5.1 ◇) can revise it, and that revision is logged as a departure in a new version — the old version stays in the lineage."
- `AGENTS.md`, *What you must not do*: "Do not alter the base code on your own authority. It changes only when a reproduced observation fires a stated falsifier, recorded as a departure in a new version."
- PR template, honesty checklist: "Base code unchanged — or changed only because a reproduced observation fired a stated falsifier, logged explicitly as a departure."
