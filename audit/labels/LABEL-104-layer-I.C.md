## Scientific Inquiry run

1. Question (precise): Does a registry of ten author-selected domains support the label "Universal", i.e. that the base code holds in every process domain?
2. What an answer must look like: Either an exhaustive enumeration of domains, or a test with independently chosen domains and a criterion that some domain could fail.
3. Falsifiability condition: "Universal" is supported only if the mapping could fail for some domain and has been tested where failure was possible.
4. Variables: measurable / bounded / held open: Measurable: the ten mappings as written. Bounded: ten of an unknown number of domains. Held open: universality; whether any process description lacks an input, a transformation, or an output.
5. Test designed: Read the registry and ◇ row; check for a failure criterion and a sampling rule.
6. Data (unfiltered): Ten domains, selected and mapped by the author. The text states a resisting domain "becomes a named variable, not a disproof", which removes the registry's ability to fail. Any process described as input → transformation → output fits the mapping by construction.
7. Variable Principle applied: Ten mapped domains bound the claim to ten. "Universal" and "Zero Exceptions" fill the remaining range with assumption. Held open.
8. Model update (Capsule: what the failed parts contribute): The registry keeps its value as a set of ten worked mappings. The name narrows to its measured extent: ten domains.
9. Documented: This file. Correspondence: one scale up, v5.1 Appendix D describes its constants registry as "a working set … incomplete enough to require v6 to extend it"; the same working-set wording would fit I.C and is the canon precedent for the proposed name.
10. Next baseline: Proposed for v5.5 (not applied): "The Ten-Domain Process Registry". Open question (routed to a CLAIM audit on the ◇ row): what observation would count as a process with DETECT → PROCESS → RESPOND "entirely absent"? Re-review 2027-09-24.

## Forcing Test

- Test A (Ground): Grounded only for the ten mappings as written; not for "universal".
- Test B (Uniqueness): Many candidates survive (holds in all domains; holds in these ten; holds by construction of the description). Not forced.
- Test C (Direction): No measurement supplies a direction beyond the ten.
- Test D (Falsifiability): ◇ states a falsifier, but I.C's own rule converts a resisting domain into "a named variable, not a disproof", so the falsifier is weak in practice.
- **Outcome:** live-hypothesis, with the caveat that its falsifier needs an operational definition before it can fire.

## Anti-Operation (the gap this opens)

If every process described as input → transformation → output fits the base code, the base code may be a property of the description rather than of the process. The gap: find a process description, drawn from a field that does not use the framework, that cannot be cut into three steps, or show that none can exist (in which case the claim is a definition, and should be filed as a stipulation).

## Narrative stripped (if any)

- "Universal" and "Zero Exceptions": not supported by ten author-selected domains; removed from the proposed name.
- "This registry is the proof set": a proof needs either exhaustion or a test that could fail; neither is present.
- "Per Correspondence … law — not analogy": a Layer II mapping; reality neither forces nor contradicts it by any measurement fetched here.
- Old name kept in lineage; nothing renamed in canon.
