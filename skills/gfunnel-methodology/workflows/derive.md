# Workflow — Derive an Algorithm (No Explicit Algorithm Exists)

Use when the domain or problem is not covered by any v5.1 algorithm (check `run-algorithm.md` §1 first). The canon: *if a new domain emerges that this framework does not yet name, run the Master Meta-Algorithm against it and the specific algorithm for that domain emerges by structural derivation.*

## Steps

1. **Read the Master Meta-Algorithm** in v5.1 (`SECTIONS.md` → *The Master Meta-Algorithm*; also summarized in `framework/algorithms.md`). Read its *Failure Modes* too.
2. **Announce the derivation before doing it**: "No primary algorithm covers <domain>; deriving one from the Master Meta-Algorithm. This is a derivation, not a primary algorithm."
3. **Run the 12 steps against the domain, in order:**
   1. Identify the domain, specifically enough that its DETECT / PROCESS / RESPOND signatures are distinguishable from neighbouring domains.
   2. Locate its Three Kingdoms alignment.
   3. Current state: capture it without filtering; hold every variable open.
   4. Desired state: the gap is the work.
   5. Dynamic middle: Yang extreme, Yin extreme, the middle between them.
   6. The Hermetic principle being violated.
   7. The gradient that powers the domain: established, collapsed, or absent.
   8. The cause that, set deliberately, produces the desired effect.
   9. The structure: Third → Second → First Kingdom, none skipped.
   10. Run the cycle; capture deviations as data.
   11. Document the result.
   12. Restart at the higher baseline.
4. **Emit the derived algorithm** as numbered steps in the same shape as the canon's domain algorithms (look at a neighbouring one in v5.1 *Domain-Specific Operational Algorithms* for format), headed:

```
<Domain> Algorithm — DERIVATION (from the Master Meta-Algorithm, v5.1).
Not a primary algorithm of the GFunnel Methodology.
```

5. **Check Correspondence**: name the nearest existing algorithm one scale up or down and what the derived one shares with it. If it resists correspondence, name that resistance as a held-open variable (v5.2 §1 step K).
6. **List what stayed open** and any empirical data the domain needs.
7. **Optionally run it** on the user's situation via `run-algorithm.md` §3–§5, still labelled a derivation.

## Never

- Present the result as part of the canon, or give it a layer number.
- Silently borrow steps from outside the framework. If you import outside knowledge (e.g. a domain's standard practice), mark it as outside input.
- Propose it into the canon without going through `iterate.md`.
