# Workflow — Diagnose and Run an Algorithm

Use for: "my business is stuck", "sales aren't converting", "I'm burning out", "run the Garlick Equilibrium on my company", "walk me through the Negotiation Algorithm", any named v5.1 algorithm.

The canon's instruction: *execute the numbered steps explicitly. Do not skip steps or compress them. The sequence is load-bearing.*

## 1. Select the algorithm

Use the routers in this order and **say which one you used**:

1. `framework/algorithms.md` → *Router (symptom → where to look)*: a symptom-to-violation table.
2. v5.1 *Algorithm Index by Problem Type* (`SECTIONS.md`): "I'm stuck", "I need to hire", "I need to handle a crisis"…
3. v5.1 *Fast-Reference Algorithm Index*: all 47 core algorithms with step counts (Master Meta, 17 per-layer, 30 domain).
4. v5.1 *Extended Domain-Specific Algorithms*: the further domains (System Architecture, Crisis Response, Project Management, Risk Management, Compliance, and others).

If two rows match, the canon often pairs them (e.g. "failing and I don't know why" → Layer II + Layer I; "close a deal" → Sales + Layer VII ACE). Run them as the index says.

When the paired algorithms overlap (the 12-step Sales Algorithm restates the 7-step Layer VII ACE algorithm operationally), run the one the index names first literally and use the other as a cross-reference. Say which you ran in full.

Some canonical algorithms name GFunnel's own offer, tiers or tooling (e.g. the ACE text and its CRM stack). Applying them to the user's own business is a **domain derivation** (rule 7): substitute the user's equivalents and say that you did.

If nothing matches, go to `workflows/derive.md`.

## 2. Load the algorithm's full text

Find its `####` heading in `SECTIONS.md` and read exactly that line range. Also read the parent layer's section if the algorithm leans on concepts (the Three Kingdoms, the Dynamic Middle, BEAS scoring, I.A.C.E.) that you need to apply correctly.

## 3. Execute, step by step

For each numbered step:

- Quote or closely paraphrase the step (so the user sees the sequence).
- Apply it to the user's situation using **only what they have told you or what you can measure**.
- When the step needs information you do not have, **stop at that step**. Ask for it, or name it as a held-open variable. Per the canon, the blocker is the location of the work, so report it as the finding rather than skipping past it.
- Do not reorder. Do not merge steps. Do not skip a step because it seems obvious.
- If length is constrained, shorten each step's text but keep **every** step. Dropping a step is not allowed.

The Master Meta-Algorithm's named failure modes apply to every run: no domain (step 1) → noise; no desired state (4) → no termination; no dynamic middle (5) → burnout or paralysis; jumping from Third to First Kingdom without Second (9) → the wrong thing perfectly built; no documentation (11) → a dependency, not a process; no restart (12) → no compounding.

## 4. Report the run

Produce a run log the user can keep (Layer VI: *if it isn't written, it doesn't exist as a process*):

```
Algorithm: <name> (v5.1, <section>)   [primary | derivation]
Situation: <one line>
Step 1 — <step>: <finding>
Step 2 — …
Blocked at: <step, and what data would unblock it>   (if any)
Violation located: <Hermetic principle / Kingdom misalignment / collapsed middle / absent gradient>
Held open: <variables not filled>
Correspondence: <same algorithm one scale up / down>   (if applicable)
Next cycle: <what to do, what to measure, what to integrate (Layer I.G)>
```

## 5. Integrate

Close with what deviated and what the next cycle should start from (Master Meta steps 11–12; Layer I.G, the Capsule). If the user reruns the algorithm later, begin from this log, not from zero.

## Depth option

If the user wants a mechanism examined at full resolution rather than a situation diagnosed, use the **v5.2 Deep-Lens Protocol** (v5.2 §1, steps A–L). It is the Master Meta-Algorithm with depth amplifiers; the five completed runs in v5.2 §3 are worked examples.
