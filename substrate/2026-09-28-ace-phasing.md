# Author Structural Decision — the methodology's own development runs on ACE

*Substrate document · 2026-09-28 · Structural read given by the author (Cameron Garlick) · Loads v5.1–v5.4, the Reality Audit, and [`2026-09-28-conservation-level.md`](2026-09-28-conservation-level.md) as prior substrate*

> **Status: substrate, not canon.** It records a structural decision about how the methodology's own versions are phased. Whether the Create phase succeeds is not decided here; §4 states the criterion by which it would be.

---

## §1 · The decision, as given

> *"So far the methodology is used for acquiring, testing, and organizing the information. When we get to v6 we can focus on the creation mechanism. So think ACE — Acquire, Create, Expand."*

The methodology's own **Layer VII (the ACE System)** is applied to the methodology's own development:

| ACE stage | Versions | What the work is |
| --- | --- | --- |
| **A · Acquire** | v5.1 → v5.5 | Acquiring, testing and organizing what is known. The Reality Audit is this stage executed. |
| **C · Create** | **v6** | The creation mechanism: producing what was not there before. |
| **E · Expand** | after v6 | Propagation — the adoption registry, other operators running it. |

## §2 · This is self-application, and canon asks for it

Canon already demands the framework be run against itself:

- v5.1 Layer 0 contains a **Self-Application Test** — *"Does Layer 0 comply with itself?"*
- v5.3 names **Layer ⊙, the Container**: *"the framework run against itself, made architectural."*
- Layer II (Correspondence) claims the same structure recurs at every scale where it applies.

Applying Layer VII to the framework's own version lineage is the same move at the scale of the document. It is a **legitimate instance of canon's own Correspondence claim**, not an outside import (substrate item 4 is satisfied: nothing external is brought in as structure).

## §3 · What this reframes in the audit's findings

The phasing is not merely tidy. It **corrects one of the audit's own gradings** and explains a cluster of others.

### 3.1 · It rescues the Master Meta-Algorithm finding

[`../audit/fullrun/RUN-018.md`](../audit/fullrun/RUN-018.md) graded the Master Meta-Algorithm **not-applicable** for the subject *"understand a bacterial cell"*: it blocks at step 6, because a working bacterium violates no principle. The run diagnosed it as *"an intervention algorithm — its arrow is operator → domain"*, and recorded canon's universality claim for it as `forced-no`.

**Under ACE phasing that diagnosis is right and the grading is wrong.** An intervention algorithm **is** a Create-phase instrument. It was being asked to do Acquire-phase work, and it declined — correctly. The defect is not in the algorithm; it is in the **routing**:

> `AGENTS.md` rule 4 sends *every* uncovered domain to the Master Meta-Algorithm, including questions of pure understanding. Canon owns an Acquire-phase instrument already — the **Scientific Inquiry Algorithm** ([`../audit/fullrun/RUN-019.md`](../audit/fullrun/RUN-019.md), graded `works-descriptive`, and the instrument this audit has executed ~270 times) — and files it *below* the universal one.

**Proposed correction:** route by phase. Acquire-phase questions → Scientific Inquiry Algorithm. Create-phase questions → Master Meta-Algorithm. The universality claim then applies **within each phase**, which is a claim canon can actually keep.

### 3.2 · It explains why the audit found zero produced knowledge

[`../audit/cost/README.md`](../audit/cost/README.md) §B records: knowledge the methodology *contains*, $158–177 B; knowledge it has *produced*, **$0 confirmed**. Under ACE phasing that is not a failure — it is the expected state of a framework that has not yet run its Create phase. The audit measured an Acquire-phase artifact against a Create-phase standard.

**The honest form of the finding therefore changes.** Not *"the framework produces nothing"* but: *"the framework has completed Acquire and has not yet attempted Create; the produced-knowledge ledger stands at zero because the phase that would fill it has not run."*

### 3.3 · It explains the business layers' position

Layers IV–VII are Create- and Expand-phase instruments (an operator setting a cause; propagation; sales). The full run applies them to a bacterium, which is an Acquire-phase subject. Wherever they grade `not-applicable` there, the phasing supplies a legitimate reading: **wrong phase, not wrong layer** — provided canon says so explicitly rather than claiming universality and then failing it. That is the check §4 imposes.

### 3.4 · What is already the bridge to Create

Two artifacts already built sit on the A→C boundary and should be declared as such:

- **Containers** ([`../containers/README.md`](../containers/README.md)) — substrate item 6. A container is an Acquire-phase result written so a Create-phase run can start from it without re-study. That is literally the handoff.
- **The Mechanism Design Algorithm** ([`../design/DESIGN-ALGORITHM.md`](../design/DESIGN-ALGORITHM.md)) — the first Create-phase instrument built, derived from the Master Meta-Algorithm. Its first run scored the audit's first hit that was **not** a restatement of existing canon ([`../audit/prediction/PRED-004.md`](../audit/prediction/PRED-004.md)), which is early evidence the Create phase has something to run.

## §4 · The discipline this phasing must carry (or it becomes an excuse)

A phase label can defer a finding indefinitely. *"Create comes in v6"* would neutralise the produced-knowledge ledger by postponement rather than by work. Three conditions keep it honest, and they are stated now, before v6 exists:

1. **Create is not declared by writing a Create chapter.** It is declared when a sealed, discriminating, low-contamination prediction **hits** — the standing bar in [`../audit/prediction/PROTOCOL.md`](../audit/prediction/PROTOCOL.md). PRED-004 hit on *process*, with contamination graded medium; that is a start, not the bar.
2. **The phase boundary does not licence lowering a grade's standard.** A Create-phase instrument that fails on a Create-phase subject fails. Phasing only rules out the *cross-phase* mis-grading of §3.1 and §3.3.
3. **Acquire does not close.** Phase 9 of the brief (re-review on `review_after` dates, re-audit on new measurement releases) continues through v6 and after. *"Completeness is a direction, not a state"* — [`2026-09-24-reality-filter.md`](2026-09-24-reality-filter.md) item 2 — applies to the phases too: A does not finish, it stops being the frontier.

## §5 · Held open

- **Whether ACE's own internal structure carries.** Layer VII has an **I.A.C.E. objection loop** inside Acquisition. If the phasing is a genuine Correspondence instance rather than a convenient label, that sub-loop should have a counterpart in the version lineage — and the audit's findings-and-response cycle is a candidate. Not claimed; held open for the v6 run to test.
- **Where v5.5 sits.** It is Acquire-phase (it records what the audit found). Whether it should also *open* Create, by declaring the container system and the design algorithm, is the author's call at Phase 8.
- **Whether Expand can begin before Create completes.** The adoption registry exists and is empty of third parties. Canon does not say whether propagating an Acquire-phase framework is legitimate or premature.
